# ADR 002 — Histórico, regras e distribuição da versão 0.3

Data: 7 de outubro de 2026. Estado: implementado.

## Problema e critérios

Usuários precisam entender resultados anteriores, controlar frequência e arquivos de checkpoints, configurar Git com orientação e instalar novas versões. O coordenador também precisa de uma implantação reproduzível com HTTPS e persistência.

Critérios de aceite: histórico limitado e persistente; regras validadas por projeto; commits automáticos sem incorporar arquivos novos ou alterações excluídas; diagnóstico sem mutações; atualização optativa com fonte HTTPS confiável e instalação explícita; deployment com dados persistentes e healthcheck público sem dados privados.

## Decisões

- Persistir os últimos 1.000 eventos em JSON com gravação atômica serializada. Projetar apenas metadados e motivos sanitizados; manter API autenticada e filtrável. Armazenamento segue destinado a uma única instância pessoal.
- Agendar cada projeto com intervalo próprio. Espera do checkpoint considera somente o diff dos arquivos permitidos. Seleção vem dos arquivos já presentes no HEAD, com nomes delimitados por NUL e pathspecs literais; `commit --only` preserva o restante do índice.
- Diagnosticar Git, repositório, upstream e identidade local sem alterar configuração e sem testar credenciais externas.
- Manter UI local sem scripts ou estilos inline, com CSP restritiva, rótulos, foco visível, feedback acessível e navegação responsiva. Preservar formulários de regras durante atualização periódica de status.
- Usar `electron-updater` com download e instalação automáticos desativados. Fonte optativa HTTPS recebe confirmação nativa; requisições e redirecionamentos ficam restritos à pasta/origem aprovada. Bibliotecas verificam SHA-512 dos artefatos. A instalação explícita aguarda o serviço parar.
- Oferecer VPS via Docker/Caddy e Render com disco. Não escolher um host, criar gastos ou publicar credenciais sem os dados do ambiente do usuário.

## Consequências

Regras de checkpoints não resolvem alterações pendentes fora da lista; o usuário deve fazer commits manualmente. A atualização exige primeiro instalar a versão 0.3 e publicar os artefatos HTTPS. O binário ainda não possui assinatura de publicador. Coordenador e histórico local não oferecem concorrência distribuída ou banco multiusuário.
