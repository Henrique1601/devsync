# ADR-001: motor local e coordenação remota

Status: Accepted
Data: 2026-10-06

## Contexto

Os mesmos projetos precisam ser controlados pela CLI, pelo desktop e por um painel acessível em outros computadores. PCs podem ficar offline. O código continua sendo transportado pelo GitHub.

## Decisão

Manter Node.js e o motor Git existentes. O aplicativo Electron executa o serviço no processo principal ou conecta a uma instância local já ativa. A janela pode ser fechada sem interromper o serviço. IPC do desktop expõe apenas seleção de pasta e preferências de inicialização, com validação de remetente, isolamento de contexto e sandbox.

Um coordenador Node.js independente mantém dispositivos e fila em disco. Cada dispositivo usa seu próprio token, gerado pelo administrador, e consulta o coordenador por conexões HTTPS de saída. O coordenador recebe somente nomes, branches e estados dos projetos, sem arquivos do repositório ou caminhos locais. O painel remoto permite sincronizar, pausar e retomar; ativar commits automáticos e envio permanece uma decisão local.

Entrega de comandos é pelo menos uma vez: se a conexão cair após a execução e antes da confirmação, o dispositivo pode repetir sincronizar, pausar ou retomar. Esses comandos são idempotentes. A fila de PCs offline persiste após reiniciar o coordenador.

Checkpoints são optativos e independentes de push. Commit automático somente após 60 segundos de estabilidade das diferenças observadas, na branch cadastrada, sem operação Git ativa ou divergência já conhecida. Arquivos não rastreados permanecem para inclusão manual. Alguns nomes comuns de arquivos sensíveis são bloqueados; isso não substitui o .gitignore nem revisão do conteúdo.

## Alternativas consideradas

- Serviço remoto armazenando código: dispensado porque duplicaria a função do GitHub.
- WebSocket permanente: menor latência, mas maior complexidade de reconexão. Polling de 10 segundos atende à primeira versão.
- Serviço Windows do sistema: exigiria instalação administrativa e outra estratégia de credenciais Git. Preferido aplicativo na sessão do usuário, iniciado no login.

## Consequências

O coordenador deve executar como uma única instância por diretório. O armazenamento JSON serve para uso pessoal; alta concorrência exigirá banco de dados. Hospedagem HTTPS, backups do diretório e token de administrador são responsabilidade do operador. Não há publicação automática em uma conta de hospedagem.

O aplicativo exige Git instalado. O instalador é gerado com Electron Builder, sem certificado de assinatura configurado. Encerrar abruptamente ainda pode deixar locks residuais. O bloqueio do serviço pode ser recuperado quando seu PID comprovadamente encerrou; origem incerta e bloqueios Git são preservados.
